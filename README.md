# Eclipse Workspace Memo

[MIT License](LICENSE) · Eclipse Marketplace 배포용 플러그인

프로젝트를 만들지 않고 **현재 워크스페이스 폴더에 텍스트 파일을 저장하고 편집**하는 이클립스 플러그인입니다.

Package Explorer와 Project Explorer **두 뷰 내부**에 `워크스페이스 파일` 영역을 추가합니다. 프로젝트가 하나도 없으면 이 영역을 전체로 표시하고, 프로젝트가 있으면 기존 프로젝트 트리 아래에 표시합니다. 구분선을 끌어 높이를 조절할 수 있습니다. 파일을 프로젝트로 등록하거나 가짜 프로젝트를 만들지 않습니다.

```text
workspace/
├─ .metadata/          # 이클립스 관리 영역, 목록에서 제외
├─ 메모.txt            # 실제 저장 위치
├─ 할일.md
├─ 일반 폴더/
└─ ExistingProject/    # 기존 프로젝트 트리에서 표시
```

## 빠른 시작

1. 아래 설치 방법 중 하나로 플러그인을 설치하고 Eclipse 또는 STS를 재시작합니다.
2. Package Explorer 또는 Project Explorer를 엽니다.
3. 탐색기 안의 `워크스페이스 파일` 영역에서 **새 메모** 아이콘을 누릅니다. 아이콘에 마우스를 올리면 이름이 표시됩니다.
4. 내용을 입력한 뒤 `Ctrl+S`를 누릅니다.
5. 파일 이름에 `메모.txt`를 입력하고 확인합니다.
6. 파일 목록에 `메모.txt`가 나타납니다. 편집기를 닫아도 목록에서 더블클릭하면 다시 열 수 있습니다.

저장 위치는 **현재 Eclipse 워크스페이스의 최상위 폴더**입니다. 프로젝트나 프로젝트 안의 `src` 폴더에 저장되지 않습니다. `워크스페이스 파일` 제목에 마우스를 올리면 실제 경로를 확인할 수 있습니다.

## 설치

| 받은 파일 | 설치 방법 |
| --- | --- |
| `eclipse-workspace-memo-update-site-1.0.1.zip` | Install New Software의 Archive로 선택 |
| `dev.eclipsememo_1.0.1.jar` | 제품 설치 폴더의 `dropins`에 복사 |
| `eclipse-workspace-memo-1.0.1.zip` | 압축을 풀고 내부 `dropins`를 제품 설치 폴더에 합쳐 복사 |

동일한 제품에는 아래 두 설치 방법 중 하나만 사용하세요.

### Install New Software로 설치

1. `Help > Install New Software… > Add… > Archive…`를 선택합니다.
2. 받은 `eclipse-workspace-memo-update-site-1.0.1.zip`을 선택합니다. 직접 빌드했다면 `dist/`에 있습니다. 압축은 풀지 않습니다.
3. `Workspace Tools > Eclipse Workspace Memo`를 선택하고 `Next > Finish`로 설치한 뒤 재시작합니다.

여러 Eclipse 또는 STS를 사용한다면 각 제품에서 설치를 진행합니다. 이미 `dropins`로 설치했다면 제품을 종료하고 `dropins`의 기존 `dev.eclipsememo_*.jar`를 제거한 뒤 이 방식으로 설치하세요.

### dropins로 설치

1. 사용할 Eclipse 또는 STS를 종료합니다.
2. 받은 `dev.eclipsememo_1.0.1.jar`를 **각 제품 설치 폴더의 `dropins` 폴더**에 복사합니다. 직접 빌드했다면 `dist/`에 있습니다. `dropins` 폴더가 없다면 만듭니다.
3. 제품을 다시 실행합니다.
4. Package Explorer 또는 Project Explorer 안에 `워크스페이스 파일` 영역이 나타납니다.

ZIP 배포 파일을 받았다면 압축을 풀고 안의 `dropins` 폴더를 제품 설치 폴더에 합쳐 복사해도 됩니다.

예시 설치 위치:

```text
C:\dev\sts-3.9.18.RELEASE\dropins\dev.eclipsememo_1.0.1.jar
C:\dev\eclipse\dropins\dev.eclipsememo_1.0.1.jar
C:\dev\sts-5.3.0.RELEASE\dropins\dev.eclipsememo_1.0.1.jar
```

### 설치 확인

`Help > About > Installation Details > Plug-ins`에서 `Eclipse Workspace Memo`를 확인합니다. 제품에 따라 About 메뉴 이름에 Eclipse 또는 Spring Tools 이름이 포함될 수 있습니다.

Package Explorer나 Project Explorer 안에 `워크스페이스 파일` 영역이 표시되면 사용할 준비가 된 것입니다.

## 사용법

### 탐색기와 화면 배치

탐색기가 닫혀 있으면 `Window > Show View > Other…`에서 `Package Explorer` 또는 `Project Explorer`를 찾아 엽니다.

- 프로젝트가 없으면 `워크스페이스 파일` 영역이 탐색기 전체를 사용합니다.
- 프로젝트가 있으면 기존 프로젝트 트리 아래에 표시됩니다. 가운데 구분선을 끌어 높이를 조절합니다.
- 두 탐색기에서 같은 워크스페이스 파일 목록을 볼 수 있습니다.
- 파일과 폴더를 외부에서 추가하거나 삭제하면 목록이 자동으로 갱신됩니다. 바로 보이지 않으면 **새로고침**을 누릅니다.

### 새 메모 작성과 저장

1. 파일 영역의 **새 메모** 아이콘 또는 `File > 새 워크스페이스 메모`를 선택합니다. 우클릭 메뉴의 `새 메모`도 사용할 수 있습니다.
2. 열린 `새 메모` 편집기에 내용을 입력합니다. 최초 저장 전에는 실제 파일이 생성되지 않습니다.
3. `Ctrl+S`를 누르고 `할일.md`, `메모.txt`처럼 확장자를 포함한 파일 이름을 입력합니다.
4. 저장 위치를 확인하고 확인 버튼을 누릅니다. 이름을 묻는 창에서 취소하면 파일을 만들지 않고 편집 중인 내용을 유지합니다.
5. 저장 후에는 같은 편집 탭에서 계속 작성하고 `Ctrl+S`로 변경 내용을 저장합니다.

새 메모는 선택한 폴더와 관계없이 **워크스페이스 최상위 폴더에 최초 저장**됩니다. 같은 이름의 파일이 있으면 덮어쓰기 여부를 묻습니다. 자동 저장 기능은 없으므로 편집 후 저장하세요. `File > Save All` 및 편집기를 닫을 때의 저장 요청도 지원합니다.

이름을 먼저 정하고 시작하려면 `File > New > Other… > General > Workspace Memo`를 선택합니다. 파일 이름을 입력하고 `Finish`를 누르면 워크스페이스 최상위 폴더에 빈 파일을 만들고 엽니다. 이미 존재하는 이름은 사용할 수 없습니다.

### 기존 파일 열기와 다른 이름으로 저장

파일 목록에서 파일을 더블클릭하거나 우클릭 메뉴의 **열기**를 선택합니다. 폴더를 펼치면 그 안의 파일도 열 수 있습니다. `.md`, `.txt` 등 텍스트 파일을 편집하며, Markdown 미리보기 기능은 제공하지 않습니다.

기존 파일을 다른 이름으로 저장하려면 해당 편집기를 선택한 뒤 `File > 워크스페이스에 저장…`을 실행합니다. 새 파일 이름을 입력하면 현재 내용을 **워크스페이스 최상위 폴더에 UTF-8로 저장**하고 같은 탭을 그 파일로 전환합니다. 다른 이름으로 저장했다면 원래 파일도 남습니다. 하위 폴더에 있는 파일도 이 명령의 저장 위치는 워크스페이스 최상위 폴더입니다.

### 폴더 만들기

1. 파일 목록에서 상위 폴더를 선택합니다.
2. **새 폴더** 아이콘 또는 우클릭 메뉴의 `새 폴더`를 선택합니다.
3. 폴더 이름을 입력하고 확인합니다.

폴더를 선택하면 그 안에, 파일을 선택하면 그 파일이 있는 폴더에 새 폴더를 만듭니다. 아무것도 선택하지 않았으면 워크스페이스 최상위 폴더에 만듭니다. 새 폴더 생성 창에 표시된 경로로 위치를 확인하세요.

하위 폴더에 메모를 배치하려면 저장한 파일의 편집 탭을 닫고 Windows 파일 탐색기 등에서 파일을 옮긴 뒤, 플러그인의 파일 목록에서 다시 여세요. 플러그인 내부의 파일 이동 기능은 제공하지 않습니다.

### 이름 변경과 삭제

| 작업 | 사용 방법 | 동작 |
| --- | --- | --- |
| 파일 이름 변경 | 파일 선택 후 `F2` 또는 우클릭 → `이름 변경…` | 새 이름을 입력하면 변경하고 파일을 다시 엽니다. 같은 이름이 있으면 변경하지 않습니다. |
| 파일 삭제 | 파일 선택 후 `Delete` 또는 우클릭 → `삭제…` | 확인 후 디스크에서 영구 삭제합니다. 휴지통으로 보내지 않습니다. |
| 폴더 삭제 | 폴더 선택 후 `Delete` 또는 우클릭 → `삭제…` | 비어 있는 폴더만 삭제합니다. |
| 목록 새로고침 | 파일 목록에 초점을 둔 뒤 `F5` 또는 **새로고침** 아이콘 | 현재 파일 목록을 다시 읽습니다. |

이름 변경이나 삭제 대상 파일이 편집 중이면 편집기를 닫는 과정에서 저장 여부를 물을 수 있습니다. 닫기를 취소하면 작업도 취소됩니다. 폴더 이름 변경은 지원하지 않습니다.

### Eclipse 기본 Untitled Text File 저장

`File > New > Untitled Text File`로 연 기본 빈 문서도 **최초 `Ctrl+S` 또는 `File > 워크스페이스에 저장…`**로 프로젝트 없이 저장할 수 있습니다.

기본 Untitled 편집기의 최초 저장 전 `Save All`과 닫을 때의 저장 처리는 Eclipse의 원래 동작을 따릅니다. 이 두 동작까지 플러그인의 저장 절차를 사용하려면 `새 워크스페이스 메모`로 작성하세요.

## 파일 이름과 인코딩

- 한글, 영문, 숫자, 공백이 포함된 이름을 사용할 수 있습니다. 확장자는 직접 입력합니다.
- 파일 이름에 경로를 입력할 수 없습니다. `폴더/메모.txt` 대신 `메모.txt`를 입력하세요.
- `\ / : * ? " < > |`, 제어 문자, 이름 끝의 점이나 공백은 사용할 수 없습니다.
- 빈 이름, `.`, `..`, `.metadata`, `.project`, `CON`, `NUL` 등 운영체제 예약 이름은 사용할 수 없습니다.
- 새 메모와 `워크스페이스에 저장…`으로 저장하는 파일은 UTF-8을 사용합니다.
- 기존 UTF-8 및 CP949 텍스트를 인식합니다. 기존 파일에 `Ctrl+S`로 일반 저장하면 인코딩을 유지합니다.

## 표시 범위와 제한

워크스페이스의 일반 파일과 폴더를 표시합니다. `.metadata`, 등록된 프로젝트 디렉터리, `.project`가 있는 프로젝트 디렉터리, 심볼릭 링크는 제외합니다. 프로젝트의 파일은 원래 프로젝트 트리에서 관리합니다. 편집 대상은 텍스트이며 바이너리 파일은 열지 않습니다. 프로젝트 밖 메모에는 이클립스의 프로젝트 빌드·리팩터링·워크스페이스 검색 등이 자동으로 적용되지 않습니다.

메모는 플러그인 전용 데이터베이스가 아닌 실제 파일입니다. 다른 도구로 열거나 백업할 수 있으며, 워크스페이스를 바꾸면 새 워크스페이스의 파일 목록이 표시됩니다. 기존 메모는 원래 워크스페이스 폴더에 남습니다.

## 문제 해결

| 증상 | 확인 및 조치 |
| --- | --- |
| `워크스페이스 파일` 영역이 보이지 않음 | Package Explorer 또는 Project Explorer를 열었는지 확인합니다. Plug-ins 목록에 `Eclipse Workspace Memo`가 있는지 확인하고, `Window > Preferences > General > Startup and Shutdown`에서 플러그인의 시작이 비활성화되어 있으면 활성화한 뒤 재시작합니다. |
| JAR를 복사했는데 설치가 반영되지 않음 | 워크스페이스가 아닌 **제품 설치 폴더의 `dropins`**에 복사했는지 확인합니다. 제품을 완전히 종료하고 한 번만 `-clean` 옵션으로 실행합니다. 예: `eclipse.exe -clean`. |
| 프로젝트 폴더가 파일 목록에 없음 | 프로젝트는 위쪽의 기존 프로젝트 트리에서 확인합니다. 등록된 프로젝트나 `.project`가 있는 폴더는 메모 목록에서 제외됩니다. |
| 외부에서 추가한 파일이 보이지 않음 | 현재 워크스페이스 경로와 표시 제외 대상을 확인하고 **새로고침**을 누릅니다. |
| 저장이나 이름 변경에 실패함 | 이름에 경로나 금지 문자가 없는지, 폴더 쓰기 권한이 있는지 확인합니다. 이름 변경 시 같은 이름의 대상이 있으면 다른 이름을 사용합니다. |
| 저장 시 대상 파일이 다른 탭에 열려 있다는 메시지가 나옴 | 대상 파일의 편집 탭을 먼저 저장하고 닫은 뒤 다시 시도합니다. |
| 폴더 삭제나 이름 변경이 되지 않음 | 폴더 삭제는 비어 있을 때만 가능합니다. 폴더 이름 변경은 지원하지 않습니다. |
| 파일을 열 수 없거나 한글이 깨짐 | 바이너리 파일 및 UTF-8·CP949 이외의 인코딩인지 확인합니다. 다른 도구에서 원래 인코딩을 확인한 뒤 사본을 UTF-8로 변환해 여세요. |

오류가 계속되면 Eclipse의 `Error Log` 뷰 또는 해당 워크스페이스의 `.metadata/.log`에서 `dev.eclipsememo` 관련 메시지를 확인할 수 있습니다.

## 업데이트와 제거

### Install New Software로 설치한 경우

- **업데이트:** 새 버전의 업데이트 사이트 ZIP을 `Help > Install New Software… > Add… > Archive…`로 선택하고 설치한 뒤 재시작합니다.
- **제거:** `Help > About > Installation Details > Installed Software`에서 `Eclipse Workspace Memo`를 선택하고 `Uninstall…`을 진행한 뒤 재시작합니다.

### dropins로 설치한 경우

- **업데이트:** 제품을 종료하고 `dropins`의 기존 `dev.eclipsememo_*.jar`를 제거한 뒤 새 버전 JAR를 복사하고 재시작합니다.
- **제거:** 제품을 종료하고 복사했던 `dev.eclipsememo_*.jar`만 제거한 뒤 재시작합니다.

플러그인을 제거해도 워크스페이스에 저장한 메모 파일은 그대로 남습니다.

`build-release.ps1`로 만든 `dist/release/1.0.1/`의 파일을 GitHub Releases에 올린 뒤, `.github/workflows/publish-update-site.yml` 워크플로를 저장소에 등록하고 **Publish Eclipse update site**를 수동 실행하면 해당 릴리스의 p2 업데이트 사이트를 GitHub Pages에 게시할 수 있습니다. 공개 저장소 주소를 코드에 미리 고정할 필요가 없습니다.

배포 대상 저장소는 `pinnpublic/eclipse-memo`입니다. 기본 GitHub Pages 설정을 사용할 때의 **업데이트 사이트 예정 주소**는 `https://pinnpublic.github.io/eclipse-memo/`입니다. Pages 게시와 원격 설치를 확인하기 전에는 설치 가능한 주소로 안내하지 않습니다.

v1.0.1의 로컬 배포 준비와 p2 검증을 완료했습니다. Pages 배포와 Marketplace 등록은 아직 진행하지 않았습니다.
